# Шаблон многостраничника: языки и города

Технический каркас сайта на Next.js: несколько языков, страницы услуг,
городские версии этих страниц, приём заявок, SEO, аналитика, юридические
страницы — всё уже написано и работает.

**Дизайна и секций здесь нет намеренно.** Их ты делаешь сам — это твой сайт,
а не копия чужого. Шаблон снимает с тебя настройку окружения, маршрутизацию
языков и SEO-обвязку, чтобы лимиты ушли на дизайн и содержание, а не на
конфиги. Если ты открыл его в ожидании готового сайта — готового сайта тут
нет, тут есть фундамент, на котором его быстро собрать.

## Чем это отличается от шаблона лендинга

Лендинг — одна страница на одном языке. Здесь страниц много, и берутся они
не поштучно, а перемножением:

```
языки × (общие страницы + города × страницы, у которых есть городская версия)
```

Это и называется **матрицей**. В шаблоне из коробки два языка (`ru`, `kk`),
два города-заглушки и две услуги-заглушки — матрица уже на 30 страниц:

| Адрес | Что это |
| --- | --- |
| `/` | главная на основном языке |
| `/kk` | она же по-казахски |
| `/uslugi`, `/uslugi/<услуга>` | услуги без привязки к городу |
| `/<город>` | главная города |
| `/<город>/uslugi/<услуга>` | услуга в конкретном городе |
| `/kk/<город>/uslugi/<услуга>` | она же по-казахски |
| `/kontakty` | контакты — общие, города не касаются |

Адрес собирается из трёх частей: язык, город, логический путь. Основной язык
префикса не имеет (`/uslugi`, а не `/ru/uslugi`) — второй адрес у той же
страницы не появляется. Город — необязательный сегмент перед логическим
путём. Переключатель города меняет в адресе ровно один сегмент, поэтому
со страницы услуги ведёт на ту же услугу в другом городе, а не на главную.

### Почему городов должно быть немного

Каждый город умножает **все** городские страницы на каждом языке. Три услуги
и два языка — это 6 страниц на город. Добавил десятый город — получил 60
новых страниц, каждой из которых нужен свой текст, свой заголовок и свои
падежи в названии («в Алматы», «по Алматы» — падежи заполняются в брифе,
именительный в заголовке читается как машинный перевод).

Больше 500 страниц в матрице — чек-лист на главной предупредит:
столько собирается долго, а на бесплатном тарифе Vercel сборка ограничена
по времени. Это не запрет, а повод сократить список городов до тех, где
ты действительно работаешь.

### Почему уникальный текст важнее количества страниц

Соблазн такой: взял 30 городов, размножил на них одну и ту же услугу,
получил 30 страниц под 30 запросов. Так это не работает. Страницы, у которых
меняется только название города в заголовке, поиск считает дублями и
выбрасывает из индекса пачкой — вместе с той единственной, которая была
нормальной.

Поэтому у пары «услуга + город» есть **необязательный** уникальный текст
(`lib/content/city-service.ts`): цены именно в этом городе, сроки выезда,
районы, местные особенности. Чек-лист на главной и `/seo-check`
показывают, у скольких пар такого текста нет. Правило простое: **лучше три
города с честным текстом, чем тридцать с подстановкой названия.** Города,
про которые тебе нечего сказать отдельно, лучше не заводить вовсе.

## Что нужно

- Аккаунт GitHub и аккаунт Vercel — оба бесплатные
- VS Code с расширением Claude Code — ставится из маркетплейса VS Code
  по названию «Claude Code»; там ты и разговариваешь с Claude
- Node.js 24 или новее — [nodejs.org](https://nodejs.org): обычный
  установщик, «Далее — Далее — Готово», терминал не нужен
- Git — им VS Code клонирует репозиторий на третьем шаге. Не установлен —
  VS Code скажет об этом сам и даст ссылку ([git-scm.com](https://git-scm.com)),
  на macOS диалог ставит его кнопкой

Node нужен для того, чтобы сайт запускался **у тебя на компьютере**;
pnpm поверх него Claude поставит сам, командовать этим не придётся. Пока
Node не стоит, шаги 1–3 быстрого старта всё равно проходят: сайт собирает
Vercel на своих серверах, и он уже открыт по своему адресу.

## Быстрый старт

Терминал для этого не нужен ни разу: команды выполняет Claude, сборку —
Vercel.

1. **Скопируй шаблон.** Кнопка **Use this template** → **Create a new
   repository**. Получится твой репозиторий с этим кодом.
2. **Задеплой его.** [vercel.com/new](https://vercel.com/new) → войди
   в Vercel через GitHub, чтобы он увидел твои репозитории → Import Git
   Repository → выбери свой → **Deploy**. Настраивать нечего:
   Next.js Vercel узнаёт сам. Через пару минут сайт открыт на адресе вида
   `имя-проекта.vercel.app`. Красный `pnpm test` этому не мешает: сборка
   тесты не гоняет, `pnpm build` — это `next build` и ничего больше.
3. **Открой сайт и собери материалы.** На первом экране — **чек-лист того,
   что нужно принести**: тексты о бизнесе, города с падежами, услуги
   и цены, отзывы, фото, контакты, реквизиты. Ставь галочки по мере
   сбора — они хранятся в твоём браузере и привязаны к адресу: у сайта
   на Vercel и у сайта, запущенного на твоём компьютере, наборы галочек
   разные. Это самый долгий шаг, и он не про код.
4. **Открой проект в VS Code.** Source Control → Clone Repository → вставь
   ссылку на свой репозиторий. Тоже мышью.
5. **Скажи Claude `/start`.** Дальше ведёт он: поставит зависимости,
   **спросит по разделам и запишет ответы в `brief.md` сам** — размечать
   markdown и заполнять шесть таблиц руками не нужно, — перенесёт бриф
   в конфиг, спросит в чате домен (своего ещё нет — годится адрес
   от Vercel из шага 2), прогонит проверки, запустит сайт локально
   и — спросив тебя — **запушит** сделанное, чтобы Vercel пересобрал твой живой сайт.

Чек-лист исчезнет сам, когда в конфиге и контенте не останется заглушек
шаблона, — удалять его руками не нужно, и на месте первого экрана окажется
обычная главная. На сайте в интернете это случится не в момент заполнения,
а после пуша: Vercel собирает то, что лежит в GitHub.

Пункты чек-листа приходят из `brief.md`, а он один на весь сайт и написан
по-русски, — поэтому на `/kk` они тоже русские. Это твой рабочий список,
а не страница для посетителя.

`.env.local` Claude создаёт сам на пятом шаге. В git он не попадает
и с пустыми значениями ничего не ломает: форма работает в демо-режиме,
счётчики просто не рендерятся.

Фавикона шаблон не везёт — положи свой в `app/icon.png` (512×512), и Next
сам сделает из него и `<link rel="icon">`, и `/favicon.ico`. Пока файла нет,
`/favicon.ico` отдаёт честный 404.

### Если хочешь запускать сам

Ничего из этого делать не обязательно — те же команды выполняет Claude
по просьбе. Но если терминал тебе привычнее:

```bash
pnpm install
cp .env.example .env.local   # переменные окружения; можно оставить пустыми
pnpm dev
```

`lib/site.ts`, `lib/content/cities.ts` и `lib/content/services.ts` можно
заполнить и руками — Claude тем же путём переносит эти поля из заполненного
`brief.md` командой `/brand-init`, а домен спрашивает в чате.

## Как работать

1. **Собери материалы по чек-листу** с первого экрана сайта. Он же —
   разделы `brief.md`: о бизнесе, языки и города, структура, контент,
   визуал, контакты, реквизиты, домен.
2. **Скажи Claude `/start`** и продиктуй собранное в чате. Он спросит
   по разделам, разложит ответы по полям и запишет `brief.md` сам —
   включая таблицы городов с падежами на каждом языке и таблицы услуг.
   Бриф — источник правды по проекту: заполнив его один раз, ты больше
   не пересказываешь в каждом новом чате, чем занимается компания и какой
   у тебя телефон.
   Отдельно звать `/brand-init` не нужно — он шаг внутри `/start`. Зови его
   сам, только когда бриф уже заполнен и данные надо перенести заново:
   поменялся телефон, купили домен. Домен лежит в Блоке Б, а нужен сразу:
   если поле пустое, Claude спросит его одним вопросом в чате и **впишет
   ответ обратно в бриф**, чтобы бриф и конфиг не разошлись.
3. **Собирай свой сайт:** `/new-section` — блок на странице, `/new-page` —
   страница вне матрицы, `/new-city` и `/new-service` — новый город
   и новая услуга, `/add-locale` — третий язык.
4. **Скажи `/ship`, когда что-то готово.** Он прогонит проверки,
   закоммитит, спросит, пушить ли, и запушит, а Vercel сам пересоберёт сайт из этого коммита.
   Пока не запушено, на твоём адресе висит то, что было. Публикацией это
   ещё не будет: сайт остаётся закрытым от поиска, пока его не откроет
   `/deploy` — см. «Публикация».

**`pnpm test` красный на свежем шаблоне — так и надо.** В нём 18 заглушек:
6 в `lib/site.ts` (домен, телефон, WhatsApp, БИН, название, юрлицо), 6 у
городов-заглушек и 6 у услуг-заглушек. Все восемнадцать закрывает
`/brand-init` из заполненного брифа.
Деплою красный guard не мешает: Vercel собирает `next build`, тесты
в сборку не входят. Пока идёт работа над кодом, гоняй `pnpm test:unit` —
он те же тесты без guard-а и обязан быть зелёным.

## Языки

Языки объявлены в `lib/site.ts` (`locales`), первый — основной, он живёт
без префикса. В шаблоне готовы `ru` и `kk`: словарь интерфейса
(`messages/<язык>.json`), названия и падежи городов, тексты услуг.

- **Поменять местами** (сделать основным казахский) — скажи Claude
  «сделай основным казахский»; то же самое делает `/brand-init` по полю
  «Основной язык» в брифе.
- **Добавить третий язык** — `/add-locale`. Это не строка в конфиге:
  нужен весь словарь интерфейса, названия и падежи каждого города и тексты
  каждой услуги на новом языке. Команда перечислит, что именно перевести,
  и не переведёт ни слова сама — машинный перевод в заголовке виден сразу.
- **Убрать язык** — скажи Claude «убери с сайта язык kk». Тоже не одна
  строка: словарь `messages/kk.json`, подписи городов и услуг
  в `lib/content/` и тесты, которые этот язык импортируют по имени файла.
  Лишний ключ роняет проверку типов не хуже недостающего.

Забытый перевод здесь не показывается посетителю пустым местом — он роняет
`pnpm lint`. Это сделано нарочно.

**Казахский в шаблоне написан языковой моделью и вычитку носителем
не проходил.** Что именно осталось под сомнением и что с этим делать —
[KAZAKH.md](KAZAKH.md).

## Города, услуги, страницы и секции

Всё это — команды Claude: набираешь их со слешем прямо в чате, отдельно
ставить ничего не нужно.

- `/new-city` — добавить город: слаг, координаты, падежи на каждом языке,
  контакты филиала, если они свои.
- `/new-service` — добавить услугу: слаг, цена, название и текст на каждом
  языке.
- `/new-page` — обычная страница вне матрицы (о компании, доставка).
- `/new-section` — блок на уже существующей странице (преимущества, FAQ,
  отзывы): компонент в `components/sections/`, тексты на каждом языке.
  Это не новый адрес — адрес добавляет `/new-page`.

Переключатель города показывает то, что говорит адрес. Со страницы услуги
он ведёт на ту же услугу в другом городе. На общих страницах вроде
`/kontakty` города в адресе нет — там он и не меняет ничего: показаны
общие контакты компании, а филиальные живут на городских страницах.
Между визитами выбор не запоминается: это стоило бы либо статики всего
сайта, либо заметной паузы, в которую список показывает чужой город
и потом сам себя исправляет.

## Команды

Набирать их необязательно: Claude запускает те же команды по просьбе —
«поставь зависимости», «прогони тесты», «запусти сайт».

| Команда | Что делает |
| --- | --- |
| `pnpm dev` | запустить разработку |
| `pnpm test` | тесты и проверка заглушек |
| `pnpm test:unit` | те же тесты без guard-а заглушек |
| `pnpm lint` | проверка типов |
| `pnpm check-brief` | что осталось заполнить в брифе |
| `pnpm build` | сборка |

## Заявки

Токены живут в `.env.local` — скопируй его из `.env.example`, если ещё не
сделал этого на быстром старте. Пока не заполнены `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_CHAT_ID`, форма работает в **демо-режиме**: отвечает успехом
и печатает заявку в консоль. Это нормально — бота подключают в конце. Чтобы
уводить заявки в почту или CRM, положи свой файл рядом с
`lib/lead/providers/telegram.ts`.

## Юридические страницы

Тексты политики конфиденциальности и оферты — **шаблонные**. Перед запуском
сайта их обязан проверить юрист. Мы не несём ответственности за их
содержание.

Казахская версия этих страниц — не перевод проверенного русского текста,
а сгенерированный языковой моделью черновик: её не читал ни юрист,
ни носитель языка. Показывать нужно обе версии, и казахской вдобавок
к юристу нужен носитель — см. [KAZAKH.md](KAZAKH.md).

## Публикация

`/ship` и `/deploy` делают разное.

**`/ship`** — «покажи, что получилось». Проверки, коммит, вопрос «пушить?», пуш; Vercel
пересобирает сайт. Сайт при этом остаётся закрытым от поиска, поэтому
пушить можно хоть каждый час и хоть с недоделанным конфигом.

**`/deploy`** — «выпусти в люди». Он и только он переключает
`SITE.indexable` с `'private'` на `'public'` (или `'ads-only'`, если
в брифе сказано «только под платный трафик»). Руками этого делать
не нужно. Пока стоит `'private'`, сайт закрыт от поиска, `sitemap.xml`
пустой, а Lighthouse ставит низкий балл по SEO — это защита от того,
чтобы черновик уехал в индекс, а не поломка.

Дальше `/deploy` проведёт по шагам: переменные окружения, свой домен
вместо адреса `*.vercel.app`, проверка на бою. Сам проект в Vercel уже
есть с шага 2 быстрого старта, и каждый твой коммит в GitHub пересобирает
его автоматически. Перед публикацией полезно `/seo-check`.
