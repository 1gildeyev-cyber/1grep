# Добавление языка к собранному сайту

Мультиязычность здесь уже встроена (`next-intl`, `SITE.locales`), поэтому
задача не в том, чтобы поднять инфраструктуру, а в том, чтобы безопасно
расширить контент. **Эта команда не переводит ни слова сама** — ни строку
интерфейса, ни название города, ни падеж, ни текст услуги. Машинный
перевод в заголовках (в том числе твой собственный) — это то, за что сайт
получает жалобы от посетителей, а не трафик. Если автор сайта прямо просит
«переведи сам» — откажи и укажи на этот пункт.

## Шаг 1: код языка и коллизии

Спроси код нового языка (двухбуквенный, как существующие `ru`/`kk` в
`SITE.locales`, например `en`). Прежде чем писать что-либо, проверь:

- код ещё не входит в `SITE.locales` (`lib/site.ts`);
- код не совпадает ни с одним `slug` в `lib/content/cities.ts` — при
  `localePrefix: 'as-needed'` первый сегмент адреса читается как код
  языка, если он есть в `routing.locales` (см. `lib/geo/parse-path.ts`),
  и совпадение сделает город недостижимым;
- код не совпадает с зарезервированными адресами: `uslugi`, `kontakty`,
  `politika-konfidencialnosti`, `publichnaya-oferta`, `spasibo`.

Нашёл совпадение — сообщи и попроси другой код.

## Шаг 2: перечисли, что нужно перевести

Это основной результат работы команды, когда готового перевода ещё нет.
Пройди по каждому из пяти источников и покажи автору сайта полный
список — ничего не переводя:

1. **`messages/ru.json`** — ru.json это базовый файл интерфейсных строк;
   пройди по всем его ключам рекурсивно (вложенные объекты вроде
   `lead.errors.phone`) и перечисли их — ровно этот набор ключей должен
   появиться в новом `messages/<код>.json`.
2. **`lib/content/cities.ts`** — для каждого города три поля `CityLabels`:
   `name`, `in`, `by`.
3. **`lib/content/services.ts`** — для каждой услуги три поля
   `ServiceLabels`: `title`, `short`, `body`.
4. **`lib/content/city-service.ts`** (`cityServiceTexts`) — упомяни
   отдельно: уникальные тексты пар необязательны на любом языке, но уже
   заполненные пары на других языках на новом языке всё равно будут
   пустыми, пока их не впишут вручную.
5. **`brief.md`** — таблицы в нём рассчитаны на `ru` и `kk`: «Города —
   падежи, русский», «Города — падежи, қазақша», «Услуги — русский»,
   «Услуги — қазақша» и поля «Текст (русский)» / «Текст (қазақша)»
   в списке «Тексты страниц услуг». Допиши такие же для нового языка:
   скопируй таблицу падежей и таблицу услуг, поменяв в заголовке язык,
   и добавь в каждый пункт «Тексты страниц услуг» поле
   `**Текст (<язык>):**`. Слаг в первом столбце — тот же, он и связывает
   таблицы между собой. Без этого следующий `/brand-init` пропустит
   каждый город и каждую услугу по своему же правилу отказа: у них не
   окажется строки на новом языке. Формат жёсткий — двоеточие внутри
   жирного, подсказка только до двоеточия, одна строка на ячейку.

## Шаг 3: применяй, только когда перевод готов целиком

Если автор сайта прислал перевод, закрывающий **весь** список из шага 2
(все ключи `messages/ru.json`, все города, все услуги) — вноси одним
проходом:

1. Добавь код языка в `SITE.locales` в `lib/site.ts` — в конец массива,
   первый элемент (`defaultLocale`) не трогай.
2. Создай `messages/<код>.json` с тем же деревом ключей, что в
   `messages/ru.json`, и присланными значениями.
3. В `lib/content/cities.ts` впиши присланные `name`/`in`/`by` под новым
   языком в `labels` каждого города.
4. В `lib/content/services.ts` впиши присланные `title`/`short`/`body`
   под новым языком в `labels` каждой услуги.

Если перевод пришёл лишь частично — не подставляй ничего от себя вместо
недостающего и **не добавляй код языка в `SITE.locales`**, пока не
наберётся полный комплект: `Labeled<T>` (`lib/content/types.ts`)
определён как `Record<Locale, T>`, то есть каждый `labels` без ключа
нового языка немедленно роняет `tsc --noEmit` — это нарочно, чтобы
забытый перевод не смог тихо остаться пустым на сайте. Раз файл ещё не
готов целиком, пусть язык остаётся вне `SITE.locales`, а не полу-падает
сайт.

## Шаг 4: проверка

1. `pnpm lint` — если применил шаг 3, а перевод содержимого всё же
   оказался неполным, `tsc` перечислит ровно те объекты `labels`, где не
   хватает нового ключа языка: это и есть последняя чистка списка из
   шага 2.
2. `pnpm test:unit` — обязан быть зелёным. Покраснел, разберись, а не
   игнорируй: `tests/routing.test.ts` ловит расхождение наборов ключей
   между `messages/<код>.json` и `messages/ru.json`, а
   `tests/content.test.ts` — пропущенный перевод города или услуги.
   Красная строка называет конкретный ключ. (Guard-тест `pnpm test`
   при этом может оставаться красным — это ожидаемое состояние шаблона,
   пока не заменены заглушки, и не то, что проверяет эта команда.)
3. Учти: `tests/routing.test.ts` сверяет набор ключей и «казахский не
   скопирован с русского» только для пары `ru`/`kk` по именам файлов —
   третий язык этими двумя проверками не покрыт. Совпадение ключей у
   `messages/<код>.json` с `messages/ru.json` из шага 3.2 проверь вручную.

Заверши тем же, чем заканчиваются `/new-city` и `/new-service`: пары
«услуга + город» из `lib/content/city-service.ts` на новом языке пока не
заполнены ни для одной комбинации — это не ошибка, а следующая работа
для автора сайта.
