# Новый город

Каждый город умножает количество страниц: на него заводится общая
страница (`/<город>`) и по одной странице на каждую услугу
(`/<город>/uslugi/<услуга>`) — на каждом языке сайта. Все шаги обязательны.

1. Сначала посмотри в `brief.md`, раздел «2. Языки и география»: города
   там лежат тремя таблицами (общие данные и падежи на каждый язык),
   и всё нужное ниже может уже быть вписано. Правило проекта —
   брать данные из брифа, а не переспрашивать (`CLAUDE.md`, п. 4).
   Спрашивай у автора сайта только то, чего в брифе нет:
   - **слаг** — латиницей, через дефис, без пробелов; он войдёт в адрес;
   - **координаты** — широта и долгота (`geo.lat`, `geo.lng`);
   - для **каждого** языка из `SITE.locales` (`lib/site.ts`) — три поля
     типа `CityLabels` (`lib/content/types.ts`): `name` (именительный,
     «Алматы»), `in` (предложный с предлогом, «в Алматы»), `by` (дательный
     с предлогом, «по Алматы»).
   - необязательные контакты филиала (`City.contacts` в
     `lib/content/cities.ts`): `phone`, `address`, `hours`, `mapUrl` —
     каждый независим, можно не заполнять ни один; пусто — сайт покажет
     общие контакты из `SITE`. `phone` пиши как удобно человеку
     (`+7 705 111 22 33`): в `tel:` и в разметку он уедет через
     `phoneRaw()` уже без пробелов. `hours` — тоже человеческой записью
     («Пн–Пт 9:00–18:00»); в `openingHours` её переводит
     `lib/opening-hours.ts`, а непонятую строку не выводит вовсе.

   **Не выдумывай падеж и не подставляй именительный вместо «в ком/чём» или
   «по кому/чему».** Заголовок вида «Сантехник Алматы» вместо «Сантехник
   в Алматы» читается как машинный перевод и разойдётся по всем страницам
   этого города. Не хватает падежа хотя бы на одном языке — не пиши город
   вовсе, спроси и остановись.

2. Проверь коллизии слага, прежде чем писать файл:
   - не совпадает с уже существующим `slug` в массиве `cities`
     (`lib/content/cities.ts`);
   - не совпадает ни с одним из зарезервированных адресов:
     `uslugi`, `kontakty`, `politika-konfidencialnosti`,
     `publichnaya-oferta`, `spasibo` (список `RESERVED` в
     `tests/city-routes.test.ts` — это имена реальных каталогов
     `app/[locale]/*`, слаг города не должен даже теоретически с ними
     совпасть);
   - не совпадает ни с одним кодом языка из `SITE.locales` — иначе
     `parsePath` (`lib/geo/parse-path.ts`) примет слаг города за языковой
     префикс, и город станет недостижим.

   Нашёл совпадение — сообщи и попроси другой слаг. Не придумывай замену сам.

3. Добавь запись в массив `cities` в `lib/content/cities.ts` по форме типа
   `City`: `slug`, `geo: { lat, lng }`, при наличии — `contacts`, и
   `labels` — объект с ключом на каждый язык сайта. Существующие записи
   (в том числе заглушки `gorod-odin`/`gorod-dva`) не трогай: замена
   заглушек — работа `/brand-init`, эта команда только добавляет.

4. Запусти `pnpm test:unit` — обязан остаться зелёным. Если он покраснел,
   разберись, а не игнорируй: `tests/city-routes.test.ts` и
   `tests/content.test.ts` как раз ловят коллизии и пропущенные падежи
   из шагов 1–2. (Guard-тест `pnpm test` при этом может оставаться
   красным — это нормальное состояние шаблона, пока не заменены остальные
   заглушки, и не то, что проверяет эта команда.)

5. Заверши напоминанием: у пар «услуга + этот город» пока нет
   уникального текста в `lib/content/city-service.ts`
   (`cityServiceTexts`, образец — закомментированная строка в начале
   файла). Без него поисковик может счесть городские страницы услуг
   дублями друг друга. Заполнить можно вручную хотя бы для важных пар —
   список пропущенных показывает чек-лист на главной и
   `/seo-check`.
