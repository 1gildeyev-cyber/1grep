# Новая услуга

Каждая услуга получает общую страницу (`/uslugi/<услуга>`) и по одной
странице на каждый город (`/<город>/uslugi/<услуга>`) — на каждом языке
сайта. Все шаги обязательны.

1. Сначала посмотри в `brief.md`, раздел «4. Контент»: услуги там лежат
   тремя таблицами плюс списком «Тексты страниц услуг», и всё нужное ниже
   может уже быть вписано. Правило проекта — брать данные из брифа,
   а не переспрашивать (`CLAUDE.md`, п. 4). Спрашивай у автора сайта
   только то, чего в брифе нет:
   - **слаг** — латиницей, через дефис, без пробелов;
   - **цену «от»** в тенге — необязательно; нет цены — поле `price` не
     пишешь вовсе (страница покажет `service.priceOnRequest` —
     «Цена по запросу» из `messages/*.json` — это штатное поведение,
     а не недоделка);
   - для **каждого** языка из `SITE.locales` (`lib/site.ts`) — три поля
     типа `ServiceLabels` (`lib/content/types.ts`): `title`, `short`
     (одна строка для карточки), `body` (текст страницы услуги).

   Не хватает перевода хоть одного поля хотя бы на одном языке — не
   выдумывай, не подставляй русский текст под чужой язык. Спроси и
   остановись.

2. Проверь коллизии слага, прежде чем писать файл:
   - не совпадает с уже существующим `slug` в массиве `services`
     (`lib/content/services.ts`);
   - не совпадает ни с одним `slug` из `cities` (`lib/content/cities.ts`) —
     это отдельно проверяет `tests/content.test.ts` («слаги уникальны и
     не пересекаются со слагами городов»): совпадение не ломает
     маршрутизацию (услуга живёт под `/uslugi/<слаг>`, а не на верхнем
     уровне), но делает слаг неоднозначным для человека и для будущих
     инструментов.

   Нашёл совпадение — сообщи и попроси другой слаг. Не придумывай замену сам.

3. Добавь запись в массив `services` в `lib/content/services.ts` по форме
   типа `Service`: `slug`, при наличии цены — `price: { from: <число>,
   currency: 'KZT' }`, и `labels` — объект с ключом на каждый язык сайта.
   Существующие записи (в том числе заглушки `usluga-odna`/`usluga-dva`)
   не трогай — их заменяет `/brand-init`.

4. Перелинковка с городами не требует ручной правки: страница услуги
   (`app/[locale]/uslugi/[service]/page.tsx`) и её городская версия
   (`app/[locale]/[city]/uslugi/[service]/page.tsx`) уже перебирают
   массивы `cities`/`services` целиком — новая услуга появится в списках
   сама, как только окажется в `services`.

5. Запусти `pnpm test:unit` — обязан остаться зелёным. Если он покраснел,
   разберись, а не игнорируй: `tests/content.test.ts` ловит пропущенный
   перевод и коллизию слага из шагов 1–2, и красная строка называет
   конкретную услугу и поле. Guard-тест
   `pnpm test` может оставаться красным — это ожидаемое состояние
   шаблона, пока не заменены остальные заглушки, и не то, что проверяет
   эта команда.

6. Заверши напоминанием: у пар «эта услуга + каждый город» пока нет
   уникального текста в `lib/content/city-service.ts`
   (`cityServiceTexts`, образец — закомментированная строка в начале
   файла). Без него городские страницы этой услуги поисковик может
   счесть дублями друг друга. Список пропущенных пар показывает
   чек-лист на главной и `/seo-check`.
