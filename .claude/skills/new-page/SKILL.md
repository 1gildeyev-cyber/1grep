# Новая страница

Для **общей** страницы вне матрицы город/язык (не городская, не страница
услуги — для них уже есть свои шаблоны в `app/[locale]/[city]/...` и
`app/[locale]/uslugi/...`). Делается одним проходом — все шаги
обязательны, пропуск любого означает страницу без индексации или без
перелинковки.

1. Уточни логический путь страницы (латиницей, без хвостового слеша, без
   языка и города — язык добавляет сегмент `[locale]` сам) и её назначение.
2. Создай `app/[locale]/<путь>/page.tsx`.
3. Метадата — **только** `generateMetadata` (не `export const metadata`):
   адрес зависит от языка, а язык приходит параметром маршрута.
   - `...pageMeta('/<путь>', locale)` из `@/lib/seo` — **первой строкой**
     и с **обоими** аргументами. Без `locale` казахская версия объявит
     каноническим адресом русскую и вычеркнет себя из индекса.
   - `title` — до 60 символов, без названия компании: корневой
     `app/[locale]/layout.tsx` уже задаёт шаблон `%s — ${SITE.name}`.
   - `description` — 120–160 символов, **третьим аргументом `pageMeta`**:
     `...pageMeta('/<путь>', locale, t('meta.<страница>', { name: SITE.name }))`.
     Отдельным полем `description` его не задавать: `pageMeta` ставит
     `description` и `og:description` вместе, а объявленный врозь
     `description` оставил бы странице чужой `og:description` от layout.
     Сам текст — ключом `meta.<страница>` в **каждом** файле
     `messages/<язык>.json`: описание обязано быть на языке страницы,
     иначе казахская версия объявит `hreflang=kk` поверх русского текста.
     Нет перевода — оставь ключ пустой строкой (тега просто не будет)
     и скажи об этом автору; русский текст под чужой ключ не подставляй.
   - Картинку превью `pageMeta` подставляет сама. Нужна странице своя,
     отдельная — задай `openGraph.images` явно, поверх `pageMeta`.
4. Тексты страницы — в `lib/content/<страница>.ts`. Интерфейсные подписи
   (не контент страницы, а элементы вроде кнопок и подписей полей) — через
   `getTranslations`/`useTranslations`, ключи должны существовать
   одинаковыми в `messages/ru.json` и `messages/kk.json` (и в файле любого
   ещё добавленного языка).
5. Если страница индексируется — впиши логический путь в список
   `STATIC_PATHS` внутри `lib/matrix.ts`: это единственное перечисление,
   которое питает `app/sitemap.ts`, чек-лист на главной и
   `/seo-check` — отдельного списка страниц для sitemap в проекте нет.
   Страница с `robots: { index: false }` вписывается в **оба** списка:
   в `STATIC_PATHS` — чтобы она была в логическом дереве сайта, которое
   считают `matrixSize()`, чек-лист на главной и `/seo-check`; и в
   экспортируемый `NOINDEX_PATHS` — чтобы `app/sitemap.ts` её оттуда
   вычеркнул. Ровно так там лежат `POLITIKA_PATH` и `OFERTA_PATH` —
   по одной константе на путь, в двух списках. Только в `NOINDEX_PATHS`
   путь вписывать бесполезно: этот список работает как `.filter()` поверх
   `logicalPaths()`, и путь, которого в `logicalPaths()` нет, вычёркивать
   не из чего — страница просто пропадёт из всех инструментов сразу.
6. Добавь на страницу `<Breadcrumbs path="/<путь>" locale={locale}
   segments={{ '<путь>': '<подпись>' }} />` из `@/components/seo/breadcrumbs`
   и поставь ссылку на страницу хотя бы с одной существующей — через `Link`
   из `@/i18n/navigation` (не `next/link`: тот не знает про языковой
   префикс). Страница без входящих ссылок плохо индексируется.
7. Если у страницы есть FAQ — отрендери на ней
   `<FaqJsonLd items={FAQ} pageUrl={localizedUrl('/<путь>', locale)} />` из
   `@/components/seo/json-ld` (`localizedUrl` — из `@/lib/seo`).
   Именно `localizedUrl`, а не `absoluteUrl`: тот языка не знает, и
   казахская версия страницы объявила бы в разметке русский адрес — та же
   самоканонизация, от которой предостерегает шаг 3. Вопросы и ответы —
   на языке страницы, из того же массива, из которого рендерятся
   `<details>` (правило 8): расхождение разметки и видимого текста
   поисковики считают нарушением.
8. Запусти `pnpm lint`, затем `pnpm test:unit`.
